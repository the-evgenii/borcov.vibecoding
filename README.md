# Vibe Ads Console

A server-rendered **Yii2** marketing keyword pipeline built as the `#vibecoding` homework for [borcov.group/Homework](https://borcov.group/Homework/).

It imports Google Ads, Search Console and two Ahrefs exports; removes junk, duplicates, brand terms, forbidden terms and low-volume rows; excludes keywords already used in Google Ads; merges the survivors by normalized keyword + language; generates language-specific responsive search ads; and exports a Google Ads Editor CSV for review and manual import.

> **100% vibecoded:** application code, tests and documentation were generated by an AI coding agent. This is not a no-code builder, an SPA or a wrapper around a paid API. The ad copy is deterministic, human-reviewed template copy, not AI-generated text.

## Quick start

### Requirements

- PHP 8.4+ with `pdo_sqlite`, `sqlite3`, `mbstring`, `intl`, `dom`, `fileinfo`, `curl`
- Composer 2
- A writable `runtime/` directory

### Fresh setup

```bash
cd vibecoding-marketing
composer install
cp .env.example .env
```

Edit `.env`:

```dotenv
APP_ENV=dev
APP_DEBUG=1
APP_COOKIE_VALIDATION_KEY=<64 random characters>
APP_DB_DSN=sqlite:@app/runtime/db.sqlite
APP_ADMIN_EMAIL=admin@example.com
APP_ADMIN_PASSWORD=<choose a strong local password>
```

Generate a cookie key with:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

Then run the one-time setup:

```bash
php yii migrate/up --interactive=0
php yii app/init-admin
php yii app/demo-data
```

Start the local server:

```bash
composer serve
# equivalent:
# php -d upload_max_filesize=4M -d post_max_size=4M \
#   -S 127.0.0.1:8080 -t web web/router.php
```

Open `http://127.0.0.1:8080`.

`composer setup` performs the migrate + admin + demo steps in one command. Use it only for local/demo environments; do not seed demo data in production.

## Import formats

The upload form selects the source; the file does not need to contain a source column:

- `google_ads`
- `search_console`
- `ahrefs_organic`
- `ahrefs_paid`

Both **CSV** and **JSON** are accepted. Limits: **2 MB** and **5,000 data rows** per file. UTF-8 is required; a UTF-8 BOM is tolerated. CSV delimiters `,`, `;` and tab are auto-detected on the header row.

Required fields: `keyword`, `volume`, `language`. Optional: `url`.
`volume` means monthly search frequency, not impressions or traffic. Raw Search Console exports need enrichment with search-volume data; the bundled examples contain synthetic frequency values. Decimal values use a dot or comma and round upward (12.5 or 12,5 → 13). Use no separator or a space for thousands (1200 or 1 200). Empty frequency is rejected.

Campaign exports are snapshots of the imported data and settings. Changing rules, target URLs or imports makes the previous snapshot stale: the preview explains this and CSV download is blocked until regeneration. Snapshots created before this check also require regeneration. Existing imported numbers are not retroactively reinterpreted.
Header matching is case-insensitive and ignores spaces/punctuation. The first matching column wins.

| Canonical field | Accepted aliases |
| --- | --- |
| `keyword` | `keyword`, `keywords`, `key word`, `query`, `search query`, `term`, `search term`, `phrase`, `top queries`, `top query` |
| `volume` | `volume`, `search volume`, `avg monthly searches`, `average monthly searches`, `monthly searches`, `monthly volume`, `searches` |
| `language` | `language`, `lang`, `locale`, `language code`, `target language`, `language targeting` |
| `url` | `url`, `final url`, `final urls`, `landing page`, `target url`, `page`, `link` |

Language values are normalized: `en-US`, `en_US`, `English` → `en`; `de-DE`, `deutsch` → `de`; `français` → `fr`; `русский` → `ru`. Unknown codes are preserved and reported later instead of being silently translated.

JSON may be a top-level array of objects or an object with an `items`, `data`, `keywords` or `records` array. Example: `data/demo/search_console_queries.json`.

```json
{
  "items": [
    {
      "query": "website builder for restaurants",
      "search volume": 320,
      "language": "en_US",
      "landing_page": "https://site.pro/"
    }
  ]
}
```

Empty keyword, language or frequency values reject that row. Invalid volume, invalid/relative URL, too many columns, invalid JSON and missing required columns produce explicit errors. Mixed files can import valid rows while reporting rejected rows in the batch audit.

## Cleaning and merge rules

Statuses are recalculated after every import and after settings changes:

- **Junk:** empty/letterless keywords, numeric-only keys, URLs or HTML, keywords over 80 characters or 10 words, known placeholders (`asdf`, `test`, `lorem`), repeated noise, formula-trigger characters at the start.
- **Brand:** any configured brand phrase matched as a whole normalized word phrase. Defaults: `site.pro`, `site pro`, `sitepro`.
- **Forbidden:** any configured phrase. The demo list includes multilingual forms such as `free`, `kostenlos`, `kostenloser`, `gratuit`, `gratis`, `бесплатно`, `бесплатный`, `nemokamas`, `casino` and `cheap`.
- **Already used:** every row whose source is Google Ads marks its normalized keyword + language as used, even when the same keyword also appears in Search Console or Ahrefs. Those other rows are excluded too.
- **Low volume:** volume below `min_volume` (inclusive threshold: volume must be at least the minimum).
- **Duplicate:** a later otherwise-usable row for the same normalized keyword + language. Duplicates are merged for campaign generation using the highest usable volume and a union of sources.

A source record can expose multiple reasons. The preview shows unique excluded keys and their primary reason plus detail. Google Ads source rows remain fully visible in `/keywords`.

The dashboard labels the unique surviving keywords as **Cleaned unique keywords**, records excluded at the row level as **Excluded records**, and the latest generation's ad groups as **Ready ad groups**.

## Campaign generation

One campaign is created per language, one ad group per merged keyword, and one responsive search ad (RSA) per ad group:

- Campaign name: `Site.pro | <Language> | Search`
- Campaign type: Search; networks: Google Search; budget and max CPC come from `config/params.php` (`10.00` and `0.50` by default)
- Keyword match type: Phrase
- RSA assets: **5 headlines** (max 30 characters each), **3 descriptions** (max 90 each), two display paths (max 15 each), one http(s) final URL
- Final URL comes from `Settings → language → target URL` and is the same URL used by the campaign's keyword group
- Ads are template-generated per language from reviewed copy catalogs. No translation is invented for an unknown language. The same input always produces the same assets.

Supported languages with ad copy and default (demo) target URLs:

| Code | Language | Default target URL |
| --- | --- | --- |
| `en` | English | `https://site.pro/Website-Builder/` |
| `de` | German | `https://site.pro/de/` |
| `fr` | French | `https://site.pro/fr/` |
| `es` | Spanish | `https://site.pro/es/` |
| `lt` | Lithuanian | `https://site.pro/lt/` |
| `ru` | Russian | `https://site.pro/ru/` |

The English default points to the dedicated `/Website-Builder/` page because the bare `https://site.pro/` root geo-redirected to `/de/` with German content during verification. The other language roots returned landing pages in the expected language.

The default URLs are demo values and should be reviewed before any real import. A language with no URL mapping, an invalid URL, or no reviewed ad-copy catalog is excluded with an explicit diagnostic (`missing_target_url` or `unsupported_language`) rather than generating an assumed translation.

## Google Ads Editor export

`GET /campaigns/export` builds a UTF-8 CSV (no BOM) with one entity per row. Column headers and values are based on Google's current Editor documentation:

- [Prepare a CSV file](https://support.google.com/google-ads/editor/answer/56368)
- [CSV file columns](https://support.google.com/google-ads/editor/answer/57747)
- [Import a CSV file](https://support.google.com/google-ads/editor/answer/30564)

The 26 columns are:

`Campaign`, `Campaign type`, `Campaign status`, `Budget`, `Bid strategy type`, `Networks`, `Language`, `Ad group`, `Ad group status`, `Max CPC`, `Keyword`, `Type`, `Status`, `Ad type`, `Ad name`, `Headline 1–5`, `Description 1–3`, `Path 1`, `Path 2`, `Final URL`.

Rows are emitted as campaign rows, ad group rows, keyword rows and RSA rows. Campaign language targeting uses codes such as `en`/`de`, matching Google's documented example. RSA rows use `Ad type = Responsive search ad` and include the final URL, paths and 5/3 assets.

Before download, the application validates the structure: exact header, 26 columns per row, campaign/ad group/keyword/ad entity fields, 3–15 headlines and 2–4 descriptions (the generator emits 5/3), 30/90/15 character limits, http(s) URLs, supported language, non-empty names and no duplicate campaign/ad group/keyword combinations.

### Formula-injection protection

Imported keywords beginning with `=`, `+`, `-` or `@` are treated as junk and never reach a campaign. The export additionally **fails closed**: if any exported text cell would begin with a formula trigger (including after leading whitespace) or contain a line break, the download is refused. It does **not** silently prepend an apostrophe, because that would corrupt the exact keyword/ad text imported into Google Ads. URLs and numeric budget/CPC fields are not mutated.

### Manual import step — and its limit

This project does not create Google Ads campaigns. Download the CSV, open **Google Ads Editor → Account → Import → From file**, review the proposed changes and post them manually.

> **Important limitation:** the CSV was structurally validated locally, but it was **not** imported into a live Google Ads Editor in this environment. There is no Google Ads account or Editor installation available, so "Editor-compatible" is not claimed beyond the documented column structure and local validation. Perform a dry run in Editor and review warnings before posting.

## Security notes

- Session authentication with `yii\web\User`; all business controllers use `AccessControl` with the `@` role.
- Passwords are hashed with Yii's secure password hashing (bcrypt) and verified with `validatePassword`.
- CSRF validation is enabled for all POST requests; forms include Yii's hidden token. Missing tokens return HTTP 400.
- Session cookies are `HttpOnly` and `SameSite=Lax`; set `APP_COOKIE_SECURE=1` behind HTTPS.
- `YII_DEBUG`/`YII_ENV` come from `APP_DEBUG`/`APP_ENV`; debug is enabled only when `APP_ENV=dev`, and the debug toolbar/Gii are loaded only in `dev`. The production `.env.example` uses `APP_ENV=prod`, `APP_DEBUG=0`; setting `APP_DEBUG=1` outside `dev` has no effect.
- `APP_COOKIE_VALIDATION_KEY` is mandatory in production. Secrets live only in `.env`, which is gitignored.
- Uploads are parsed in memory and never stored on disk; only normalized database rows are kept.
- Import limit is enforced in the app (2 MB / 5,000 rows) in addition to PHP's upload limits. The local serve command raises PHP's 2 MB default to 4 MB so the app limit is the effective one.
- Output is escaped with Yii's HTML helpers. The end-to-end test imports `<script>alert(1)</script>` and asserts the rendered keyword list escapes it.
- CSV formula triggers are handled as described above.
- In non-debug mode the app sends `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin` and a self-only Content Security Policy.
- No external API, queue, webhook or production account is used.

Database files, logs and uploaded test artifacts are under `runtime/` and excluded from version control.

## Deployment notes

The current isolated host deployment is documented in [`deploy/README.md`](deploy/README.md). To deploy elsewhere:

### 1. Build and environment

```bash
composer install --no-dev --optimize-autoloader
```

Set production environment values outside the repository:

```dotenv
APP_ENV=prod
APP_DEBUG=0
APP_TIMEZONE=UTC
APP_COOKIE_VALIDATION_KEY=<64 random hex chars>
APP_COOKIE_SECURE=1
APP_DB_DSN=sqlite:/var/lib/vibe-ads/db.sqlite
APP_ADMIN_EMAIL=<real admin email>
APP_ADMIN_PASSWORD=<strong password>
```

Use a strong unique admin password. `APP_COOKIE_VALIDATION_KEY` can be generated with `php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"`.

### 2. Permissions and schema

- Document root must be the project's `web/` directory, not the repository root.
- `runtime/` and `web/assets/` must be writable by PHP-FPM.
- Keep `.env`, `runtime/`, `data/`, `tests/` and `vendor/` outside the web root or deny direct access.
- Run:

```bash
php yii migrate/up --interactive=0
php yii app/init-admin
```

Do **not** run `app/demo-data` in production. For MySQL/MariaDB, set a PDO DSN and credentials through environment variables; the schema migration is portable.

### 3. Nginx example

```nginx
server {
    listen 443 ssl http2;
    server_name ads.example.com;
    root /var/www/vibe-ads/web;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$args;
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    }

    location ~ /\.(?!well-known) {
        deny all;
    }
}
```

Apache: point `DocumentRoot` at `web/`, enable `mod_rewrite`, allow the included `.htaccess`.

### 4. HTTPS and operations

- Terminate TLS at the reverse proxy; set `APP_COOKIE_SECURE=1`.
- Back up the SQLite file (or the MySQL database) before upgrades.
- Keep `APP_DEBUG=0`; never expose Yii's debug/Gii modules in production.
- Rotate the admin password and cookie validation key if they were ever shared.
- Monitor `runtime/logs/app.log` and PHP-FPM logs.
- Re-run `php yii migrate/up --interactive=0` for future migrations.
- After deploy, use the actual HTTPS URL and update the login credentials in your password manager.

The isolated host deployment is documented in [`deploy/README.md`](deploy/README.md). No Instagram/Google Ads connection was made.

## Known limitations and design decisions

- The product is a local demo: SQLite, single-node, no queue or background worker.
- Ad copy is deterministic template copy in six languages. It is not AI-generated, not translated on demand and should be reviewed by a human before posting.
- No Google Ads API, Ahrefs API, Search Console API or Google Ads account is connected. API ingestion can be added later behind the same `Importer`/`KeywordSource` boundary.
- The Google Ads Editor CSV is built against documented headers and validated locally; actual Editor import was not possible without an Editor installation/account.
- Default target URLs are demo values; verify each language URL in **Settings** before a real import.
- The demo data intentionally includes junk, brand, forbidden, duplicate, low-volume, already-used, formula-like and unsupported-language rows so the admin and diagnostics are visible.
- No SPA, CDN or external font is used; the UI is intentionally dependency-light and works offline.
- Codeception test suites are not used; PHPUnit is the test runner.
